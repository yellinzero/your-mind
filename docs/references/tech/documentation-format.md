# 技术卡片格式规范

## 概述

本规范定义 `tech/` 目录下技术卡片的格式标准。

## 卡片类型

| 类型 | 目录 | 用途 |
|------|------|------|
| **问题卡片** | `tech/problems/` | 记录技术难点及解决方案 |
| **知识卡片** | `tech/knowledge/` | 记录学习到的知识点 |

## 文件命名

- 格式：`YYYY-MM-DD-简短标题.md`
- 使用小写英文 + 连字符
- 示例：
  - `2025-12-26-connection-pool-exhaustion.md`
  - `2025-12-26-survivor-bias.md`

---

## 问题卡片模板

```markdown
---
type: problem
date: YYYY-MM-DD
tags: [标签1, 标签2]
status: draft  # draft | reviewed
---

# [问题标题]

## 问题描述

**何时遇到**：YYYY-MM-DD

**什么场景**：
[描述遇到问题的具体场景、项目背景]

**问题现象**：
[具体的错误信息、表现、影响范围]

---

## 原因分析

[问题的根本原因是什么？]

---

## 解决方案

### 尝试过的方法

1. [方法1] - 结果：[成功/失败/部分有效]
2. [方法2] - 结果：[...]

### 最终方案

[详细的解决步骤]

\`\`\`代码或配置（如有）\`\`\`

---

## 经验教训

- [从这个问题中学到了什么？]
- [下次如何避免？]

---

## 参考资料

- [来源名称](URL)

---

**创建时间**：YYYY-MM-DD
**最后更新**：YYYY-MM-DD
**审核状态**：未审核 / 已审核
```

### 问题卡片字段说明

| 字段 | 必填 | 说明 |
|------|------|------|
| 问题描述 | ✓ | 场景、现象、时间 |
| 原因分析 | ✓ | 根本原因 |
| 解决方案 | ✓ | 尝试过的方法 + 最终方案 |
| 经验教训 | ✓ | 复盘和预防 |
| 参考资料 | - | 相关链接 |

---

## 知识卡片模板

```markdown
---
type: knowledge
date: YYYY-MM-DD
tags: [标签1, 标签2]
status: draft  # draft | reviewed
---

# [知识点名称]

## 一句话概要

[用一句话解释这个知识点是什么]

---

## 详细解释

[完整的解释，包括定义、原理、机制等]

---

## 典型例子

### 例子 1：[场景名]

[具体案例描述]

### 例子 2：[场景名]

[具体案例描述]

---

## 应用场景

- [什么时候会用到这个知识？]
- [如何应用？]

---

## 常见误区

- [人们容易误解的点]

---

## 相关概念

- [[相关知识1]]
- [[相关知识2]]

---

## 参考来源

- [来源名称](URL)

---

**创建时间**：YYYY-MM-DD
**最后更新**：YYYY-MM-DD
**审核状态**：未审核 / 已审核
```

### 知识卡片字段说明

| 字段 | 必填 | 说明 |
|------|------|------|
| 一句话概要 | ✓ | 简洁定义 |
| 详细解释 | ✓ | 完整说明 |
| 典型例子 | ✓ | 至少一个具体案例 |
| 应用场景 | - | 何时使用 |
| 常见误区 | - | 避免误解 |
| 相关概念 | - | 知识网络 |
| 参考来源 | - | 出处链接 |

## 标签系统

每种卡片有独立的标签索引：
- 问题卡片：`tech/problems/tags.md`
- 知识卡片：`tech/knowledge/tags.md`

### Frontmatter 中使用标签

```yaml
tags: [高并发, 云服务器, 性能问题]
```

### 新增标签

如果需要添加新标签，同步更新对应的 `tags.md` 文件。

---

## 审核流程

1. 完成卡片编写
2. 调用 `tech-reviewer` 技能进行审核
3. 根据审核报告修正内容
4. 更新 frontmatter 中的 `status` 为 `reviewed`
5. 更新「最后更新」时间

---

## 内容要求

### 准确性

- 引用官方文档或权威来源
- 标注版本信息（如适用）
- 区分事实与个人观点

### 可操作性

- 步骤清晰、可执行
- 提供具体示例
- 说明前置条件

### 完整性

- 覆盖核心要点
- 包含常见问题
- 提供参考资料

---

## 更新维护

- 发现过时信息时及时更新
- 更新后重新审核
- 记录「最后更新」时间
